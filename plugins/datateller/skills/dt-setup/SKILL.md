# DataTeller: настройка в приложении

Только Codex desktop: этот сценарий использует его Setup и Review hooks. Если клиент
другой, не обещай ему эти элементы: объясни границу и используй его штатное подключение.
Не переносить Codex-инструкции доверия в Claude, Cursor или прямое MCP-подключение.
Отвечай на языке пользователя. Все шаги пользователя проходят внутри приложения,
кроме открытого клиентом окна входа DataTeller; не отправляй его в терминал.

1. **Подключение.** Если OAuth ещё не завершён, предложи штатное подключение DataTeller
   в карточке установленного плагина. Вход в аккаунт и выбор проектов выполняет пользователь.
   После возвращения в этот setup-чат прочитай `datateller_whoami` и проверь разрешённые
   проекты. Не создавай данные и не расширяй доступ ради проверки.
2. **Два хука.** OAuth не подтверждает доверие локальным хукам. Объясни: PostToolUse
   помогает агенту оценить полученные результаты, Stop завершает предложение оценки
   найденного источника. Предложи **Review hooks** у поля ввода этого чата. Если кнопка
   не видна, открой вместе с пользователем карточку DataTeller в Plugins: Hooks → Review.
   Не обещай автоматическое открытие диалога. Если нет обоих путей, останови настройку
   с точным ограничением клиента; не придумывай ссылку или альтернативное разрешение.
3. **Личное подтверждение.** Доверие подтверждает сам пользователь в родном диалоге:
   только два хука DataTeller — PostToolUse и Stop. Не подтверждай их за пользователя,
   не меняй настройки клиента и не обходи проверку доверия. При отказе оставь хуки
   недоверенными. Подключённые данные доступны независимо от этого решения.
4. **Проверка готовности.** Не объявляй готовность оценок только по установке, OAuth
   или словам о нажатой кнопке. Отдельно сообщи: доступ к проектам проверен либо нет;
   доверие подтверждено пользователем либо ещё не подтверждено; исполнение хуков
   и форма проверены фактически либо пока не проверены. Штатная read-only диагностика
   допустима, если она доступна в клиенте. Не вызывай хуки вручную и не создавай
   фиктивные receipt, ответы или оценки для проверки. Следующий реальный запрос
   пользователя проверяет работу; не повторяй вопросы и не запускай цикл проверки.

Оценку своей уверенности агент даёт по действующей серверной методике и собственным
основаниям, без подстановки баллов и без сужения охвата подходящих деловых вызовов.
Оценку человека предлагает только совместимая нативная форма: 4 варианта без заранее выбранного ответа.
Если такой формы нет — молча пропусти вопрос об оценке, не заменяй его текстовым
вопросом или просьбой ответить цифрой. Наличие Review hooks не доказывает наличие формы.
